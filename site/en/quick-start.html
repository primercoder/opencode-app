QUICK START · 0.1.1

Connect to opencode in three steps.

Run the host next to opencode, operate it from the phone, and add a relay only when you leave the LAN. Commands below use Linux x64; swap the archive name for arm64 when needed.

Before you start

opencode 2.x is running; the phone and computer share a network, or you have a relay ready; the APK matches the phone ABI.

Get the latest release ↗
A relay is optional. Prefer direct LAN: one less network boundary and one less service to maintain.
01

Start the host

Extract the host archive and run it. The host reads the local opencode service registration; the opencode password stays on the computer.

HOST · LINUX X64
tar xzf ocremote-host-0.1.1-linux-x64.tar.gz
cd ocremote
./ocremote start --listen 0.0.0.0:8787 --pair

On arm64 use ocremote-host-0.1.1-linux-arm64.tar.gz. It runs in the background by default; manage it with ./ocremote status, clients and stop.

02

Install and pair the phone

Use android-arm64-v8a.apk on a real device and android-x86_64.apk on an x86_64 emulator. Open the app, tap +, then scan the host QR or paste the pairing link.

ANDROID
adb install ocremote-0.1.1-android-arm64-v8a.apk

Compare the host fingerprint before connecting. Pair codes are single-use and expire after five minutes by default. The device token is stored in Android SecureStore.

03

Add a relay only when needed

The relay is a static Go binary that forwards encrypted frames. It creates TLS material and a one-time host invite; the host puts relay access into its next pairing code.

RELAY · OPTIONAL
./ocremote-relay init --data-dir ./data \
  --public-url wss://relay.example/ws

./ocremote-relay serve --data-dir ./data --listen :8443

Give the host invite to the host:

HOST · RELAY ENROLL
./ocremote start --listen 0.0.0.0:8787 --pair \
  --relay-link 'ocremote-relay://enroll#...' \
  --relay-ca ./data/tls/ca.crt

For a self-signed relay, install the CA into the Android system store or use a public CA. Release APKs do not include the development test CA.

The minimum connection facts.

The host listens locally by default. For a direct phone connection, bind 0.0.0.0 or a LAN address and allow TCP 8787 through the firewall.
