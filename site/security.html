SECURITY MODEL

中继可以转发，
但不能读懂。

手机和主机之间始终是 Noise NK 端到端加密。中继与主机、手机之间再用 Noise NK 完成身份认证和控制帧保护；TLS 是可选的额外传输层。中继只把应用数据当作密文转发，并暴露必要的路由元数据。

谁看见什么。

opencode 只绑定 127.0.0.1。主机端读取本机注册信息和密码，手机不接触 opencode 密码。

从一次性代码开始。

配对码把主机身份和传输线路交给手机；设备令牌只用于之后的认证。主机不保存明文令牌。

看配对步骤 →
01

主机生成配对码

包含主机 Noise 静态公钥、指纹、一次性 pair code 和传输线路；默认 5 分钟过期，可生成只读配对码。

02

手机核对指纹

手机显示主机指纹，和电脑上的输出逐段核对，避免连接到伪装的主机。

03

主机返回设备令牌

主机只保存 token 哈希和设备范围；手机把 token 保存在 Android SecureStore。

04

每次连接重新握手

X25519 临时密钥完成 Noise NK 握手，之后所有 OCRP 控制帧和代理负载都在受保护记录内。

这套模型保护的是手机到主机之间的应用数据。它不试图防御已经失去控制权的电脑，也不隐藏中继需要的路由元数据。

中继仍能看到谁在什么时候连接、房间大小和流量模式。Noise 保护的是应用负载，不是元数据匿名性。开放主机登记受默认 3 台主机、每房间 3 台手机的上限约束，可用 admin revoke 释放名额。

认证与传输分层。

Noise NK 认证在所有构建中启用，不依赖证书。Release 和 QA 的区别在 application id 和可选 TLS 的 CA 信任范围。

构建application id可选 TLS 信任
Releaseapp.ocremote.androidAndroid 系统 CA 库
QAapp.ocremote.android.qa系统 CA + 开发测试 CA

Noise NK 不需要 CA，所有构建都能直接使用。只有启用 wss:// 且使用自签证书时，才需要把 CA 安装到 Android 系统信任库，或改用公共 CA 签发的证书。
