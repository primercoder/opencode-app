SECURITY MODEL

中继可以转发，
但不能读懂。

手机和主机之间始终是 Noise NK 端到端加密。直连模式只多一层可替换的传输；中继模式把应用数据当作密文转发，并暴露必要的路由元数据。

01 / 数据路径

谁看见什么。

opencode 只绑定 127.0.0.1。主机端读取本机注册信息和密码，手机不接触 opencode 密码。

02 / 配对

从一次性代码开始。

配对码把主机身份和传输线路交给手机；设备令牌只用于之后的认证。主机不保存明文令牌。

看配对步骤 →
01

主机生成配对码

包含主机 Noise 静态公钥、指纹、一次性 pair code 和传输线路；默认 5 分钟过期，可生成只读配对码。

02

手机核对指纹

手机显示主机指纹，和电脑上的输出逐段核对，避免连接到伪装的主机。

03

主机返回设备令牌

主机只保存 token 哈希和设备范围；手机把 token 保存在 Android SecureStore。

04

每次连接重新握手

X25519 临时密钥完成 Noise NK 握手，之后所有 OCRP 控制帧和代理负载都在受保护记录内。

03 / 密钥与边界

密钥在哪里，边界在哪里。

这套模型保护的是手机到主机之间的应用数据。它不试图防御已经失去控制权的电脑，也不隐藏中继需要的路由元数据。

数据位置保护方式
主机 Noise 私钥~/.config/ocremote/identity.json文件权限 0600，不离开主机
设备令牌手机 SecureStore；主机保存哈希可单独撤销设备
中继 subject secret手机 SecureStore；中继保存哈希长期有效，可 revoke
中继邀请一次性 host / phone invite使用后失效，默认短时有效
中继 TLS 私钥data/tls/relay.key0600；发布包不包含生成材料
中继仍能看到谁在什么时候连接、房间大小和流量模式。Noise 保护的是应用负载，不是元数据匿名性。

04 / 发布版

Release 与 QA 分开。

发布 APK 和 QA APK 使用不同 application id 和证书信任策略。Release 只使用 Android 系统 CA 库。

构建application idTLS 信任
Releaseapp.ocremote.androidAndroid 系统 CA 库
QAapp.ocremote.android.qa系统 CA + 开发测试 CA

测试 CA 只用于开发环境。自签中继如果要在 Release APK 上使用，需要把 CA 安装到 Android 系统信任库，或者给中继换成公共 CA 签发的证书。
